# ASSORTE — Blog Sprint v4: блог и статьи-лендинги. Брифинг для Claude Code

**Задача:** превратить существующий раздел статей в **Блог**, где каждая статья — одновременно полезный материал для поиска (SEO) и посадочная страница (лендинг), которая ведёт к покупке. Статья пишется в админке и автоматически выглядит в фирменном стиле ASSORTE (как эталон).
**Эталон внешнего вида:** `docs/reference/blog-article-reference.html` — статья про павербанк Baseus PicoGo 45W. Положи его в репозиторий перед стартом.
**Язык сайта и статей:** украинский. **Язык отчётов основателю:** русский.

> v4 заменяет все предыдущие версии. Админка статей уже существует; параллельную систему не строим. Публичный раздел — **Блог**, путь **`/blog/[slug]`**. Старый путь `/articles/*` → 301-редирект на `/blog/*`. Сайт пока в разработке на `assorte.vercel.app`, реальный домен будет позже.

> Принцип: сначала инспекция и план, потом код, потом проверка с реальным выводом. Не заявляй, что что-то работает, без запуска команд.

## Архитектура (утверждена основателем)

```
Главная
 └─ нижние промо-блоки («Блоки на головній»)
      └─ кнопка «Читати статтю» ──► /blog/<slug>  (статья-лендинг)
                                        ├─ полезный контент под поисковый запрос
                                        ├─ товар внутри текста (карточка с ценой и «У кошик»)
                                        ├─ CTA в финале + липкая кнопка на мобильном
                                        └─ «Товари зі статті» внизу ──► /products/<slug> ──► корзина
Меню «Блог» ──► /blog (список статей)
Категория ──► блок «Корисні статті» ──► /blog/<slug>
Google ──► /blog/<slug>  (информационный запрос, напр. «як вибрати павербанк»)
```

**Роли страниц, чтобы они не конкурировали в поиске:**

| Страница | Целевой запрос | Задача |
|---|---|---|
| `/blog/<slug>` | информационный: «як вибрати павербанк», «павербанк у літак» | привлечь из поиска, объяснить, довести до товара |
| `/products/<slug>` | товарный: «Baseus PicoGo 45W купити», «ціна» | продать |
| `/category/<slug>` | категорийный: «гаджети для подорожей» | показать подборку |

Статья всегда ссылается на товар; товар может ссылаться на статью («Як обрати — читайте в блозі»). У статьи и товара — разные title и H1.

## 2. Решение: Markdown + директивы

Формат остаётся Markdown — основатель уже в нём работает. Добавляем:

- **`remark-gfm`** — таблицы.
- **`remark-directive`** — спецблоки.
- Санитайзер (`rehype-sanitize`) со списком разрешённых тегов/атрибутов: `style`, `script`, `iframe`, `on*` запрещены.
- **Один** компонент рендера `components/blog/ArticleBody` используется и на сайте, и в превью «Як виглядатиме». Превью должно совпадать с сайтом пиксель в пиксель.

### Синтаксис (документируй его в подсказке под редактором)

Обычная разметка стилизуется автоматически — спецсинтаксис не нужен:

```markdown
## Заголовок розділу
### Підзаголовок
### 1. Пронумерований підзаголовок      ← цифра стає червоною автоматично
**жирний**   ==червоний акцент==         ← ==…== = ключова цифра/факт червоним
- пункт списку
| Колонка | Колонка |                    ← таблиця в фірмовому стилі
| --- | --- |
![alt-текст](url "Підпис під фото")      ← фото з підписом
```

Спецблоки:

```markdown
::label[01 · Огляд]                      ← червона мітка над H2

:::summary                               ← «Коротко»
Текст блоку з **жирним** і ==акцентом==.
:::

:::important                             ← «Важливо»
Текст.
:::

:::stats                                 ← картки з великими цифрами (2–4)
- ≈ 24 Вт·год | корисна енергія
- 1,3–1,6× | смартфон на 4 000–5 000 мАг
:::

:::formula
Вт·год = мАг × 3,7 / 1000
:::

:::table{variant="accent"}               ← таблиця з червоною шапкою
| Сценарій | Що шукати |
| --- | --- |
:::

:::conclusion{title="Головний висновок" button="Переглянути техніку та гаджети" href="/category/tech-gadgets"}
Текст висновку.
:::
```

Лендинговые блоки (товар внутри статьи):

```markdown
::product{slug="baseus-picogo-45w"}      ← карточка товару: фото, назва, ціна, «У кошик», «Детальніше»

::products{slugs="slug-1,slug-2,slug-3"} ← 2–3 товари в ряд для порівняння

:::cta{button="Переглянути Baseus PicoGo 45W" href="/products/baseus-picogo-45w"}
Короткий заклик посередині статті.
:::
```

Правила для товарных блоков:
- Цена, наличие и название **берутся из базы товаров на сервере** в момент рендера — никогда не пишутся в текст статьи.
- Товар не опубликован, нет цены или нет в наличии → блок **не показывается** покупателю, в превью админки — жёлтая пометка «товар недоступний».
- Кнопка «У кошик» использует существующую логику корзины; цена в корзине — серверная.

Неизвестная директива или ошибка синтаксиса — не ломает страницу: блок показывается как обычный текст, а в превью админки — с жёлтой пометкой «невідомий блок».

## 3. Implementation

### Этап A — новые поля статьи (миграция + форма)

Существующие поля не трогай. Добавь недостающие:

| Поле | Тип | Правила | Подпись в форме |
|---|---|---|---|
| `seo_title` | text, null | ≤ 60 символов, счётчик; пусто → берётся «Заголовок» | SEO-заголовок (для Google) |
| `meta_description` | text, null | 120–160 символов, счётчик; пусто → «Короткий анонс» | Опис для Google |
| `title_accent` | text, null | должен входить в «Заголовок» | Частина заголовка червоним |
| `eyebrow` | text, null | ≤ 60 символов | Надпис над заголовком |
| `category_slug` | text, null | одна из 4 категорий | Категорія статті |
| `cover_alt` | text, null | обязателен, если есть обложка | Опис обкладинки (alt) |
| `faq` | jsonb `[]` | `{q, a}`; повторяемые поля | Питання й відповіді (FAQ) |
| `sources` | jsonb `[]` | `{label, url}`; url валидный | Джерела |
| `published_at` | timestamptz | ставится при первой публикации | — |
| `updated_at` | timestamptz | обновляется при каждом сохранении | — |
| `primary_product_id` | uuid, null, FK на товары | один главный товар статьи | Головний товар статті |
| `target_query` | text, null | для основателя, на сайт не выводится | Цільовий запит (напр. «як вибрати павербанк») |

«Короткий анонс» используется как лид под H1 и как fallback для meta description.

Валидация — Zod **на сервере**. Сохранять может только админ (сервер + RLS). Аноним читает только опубликованные статьи.

### Этап C — удобство в админке

1. Кнопка **«Вставити блок ▾»** рядом с «Вставити фото в текст»: меню с шаблонами всех спецблоков, вставка в позицию курсора.
2. «Вставити фото в текст» после загрузки спрашивает alt и подпись и вставляет `![alt](url "підпис")`.
3. Подсказка под редактором — шпаргалка по синтаксису из раздела 2 (сворачиваемая).
4. Счётчики символов для `seo_title` и `meta_description` (норма / слишком длинно).
5. Предупреждения перед публикацией (не блокируют): нет обложки или её alt, нет meta description, фото без alt, нет FAQ, неизвестные блоки в тексте.

### Этап D — публичные страницы


1. **`/blog/[slug]`** — статья. Хлебные крошки: Головна → Блог → Назва. ISR + `revalidatePath` при сохранении в админке: изменения видны без деплоя.
2. **`/blog`** — список опубликованных: обложка, eyebrow, заголовок, анонс, дата, время чтения; новые сверху. Если страница уже есть — приведи к стилю.
3. На `/category/[slug]` — блок «Корисні статті» (1–3 статьи с этой `category_slug`); нет статей — блок скрыт.
4. Пункт меню «Статті» переименовать в «Блог». Утверждённый дизайн главной не ломай.
5. `/articles` и `/articles/<slug>` → 301 на `/blog` и `/blog/<slug>`.
6. На странице товара — ссылка «Як обрати — читайте в блозі» на статью, где этот товар указан как `primary_product_id` (если есть).

### Этап E — SEO

- `generateMetadata`: `seo_title`, `meta_description` (с fallback), canonical `NEXT_PUBLIC_SITE_URL` + `/blog/<slug>`, Open Graph (`type: article`, `locale: uk_UA`, image = обложка), Twitter card.
- JSON-LD: `Article` (headline, description, image, datePublished, dateModified, publisher ASSORTE), `BreadcrumbList`, `FAQPage` из поля `faq` (только если FAQ не пустой). **Без** `Product`, `Review`, `AggregateRating` в статьях.
- Неопубликованная статья: для анонима 404, `noindex`, не в sitemap.
- `sitemap.ts`: `/blog` и все опубликованные статьи, `lastModified = updated_at`. `robots.ts` не блокирует `/blog`.
- `<html lang="uk">`, ровно один H1 на странице (H1 только из поля «Заголовок»; `# ` внутри текста превращать в H2 и показывать предупреждение в админке).
- Изображения: `next/image`, явные размеры, обложка `priority`, остальные lazy.
- Смена slug у опубликованной статьи → 301-редирект со старого адреса.
- **Домен разработки не индексируется.** Пока сайт на `*.vercel.app` (или `NEXT_PUBLIC_SITE_URL` не задан как боевой домен): `robots.txt` → `Disallow: /`, на всех страницах `noindex`. Индексация включается только на боевом домене одной переменной окружения. Canonical везде строится от `NEXT_PUBLIC_SITE_URL`.
- Внутренняя перелинковка: статья → главный товар и категория; категория → статьи; товар → статья; главная → статьи (через промо-блоки).

### Этап G — промо-блоки главной ведут в статьи

1. В админке «Блоки на головній» у кнопки блока добавь тип ссылки: **«Стаття» (выбор из списка опубликованных статей)**, «Товар», «Категорія», «Свій URL». Хранить ссылку на сущность (id), а не готовый URL — тогда смена slug статьи не ломает кнопку.
2. Если блок ведёт на статью — подпись кнопки по умолчанию «Читати статтю».
3. Если связанная статья снята с публикации — блок на главной не показывается (или показывается без кнопки — согласуй с основателем), в админке — предупреждение.
4. Блок «Надійний павербанк для активного життя» связать со статьёй про павербанк.

### Этап H — измерение (лендинговая задача)

Без платных сервисов. Используй то, что уже есть в проекте (Vercel Analytics / GA4); если ничего нет — предложи вариант основателю и **не подключай без согласия**.

События: `article_view`, `article_scroll_50`, `article_product_click` (с `product_id` и местом: inline / sticky / bottom / conclusion), `add_to_cart` с источником `article:<slug>`, `home_block_click`. В заказ при оформлении сохраняй источник первого касания (`utm` или `article:<slug>`), если в схеме заказов есть подходящее поле; если нет — опиши, что нужно, но схему заказов не меняй без согласия.
